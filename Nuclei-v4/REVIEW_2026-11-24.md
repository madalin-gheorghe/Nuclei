### R1 · P1 · Partial solver construction cleanup — fixed; native wrapper releases measured at two failure stages

- Sources: [engine allocation](Nuclei4.Gpu.D3D11/GpuFullSlimeSolverEngine.cs#L497),
  [constructor tail](Nuclei4.Gpu.D3D11/GpuFullSlimeSolverEngine.cs#L530),
  [assignment](Nuclei4/Solver_GPU.cs#L364),
  [caller cleanup](Nuclei4/Solver_GPU.cs#L1346).
- Baseline evidence: before the fix, the constructor created the device, shaders, buffers and preview
  textures, then performed dispatch/readback without a constructor-level cleanup
  guard. If a later allocation/dispatch throws, assignment to `fullSolverEngine`
  never completes. The caller's catch only disposes the assigned field.
- Consequence: partial resources lack explicit release during failed initialization;
  repeated retries can retain native/GPU memory until wrapper finalization. This is
  source-confirmed exception-safety failure, not a measured permanent leak.
- Correction: guard initialization with cleanup of the partially constructed owner
  and rethrow. Verify injected failures after device/shader/buffer creation and
  repeated reset, without altering successful dispatch or preview behavior.

- Implementation update (2026-11-25): the constructor now catches initialization
  failures after argument validation, attempts cleanup of acquired disposable fields,
  collection items and dictionary values, then uses bare `throw` to preserve the
  initialization exception. Fields are sorted by descending metadata token so
  views are attempted before their buffers/textures; context and device are last.
  Each release failure is isolated. The nested gradient wrapper also attempts both
  view and texture disposal and rethrows the first cleanup error with its stack.
  Net48 and net7.0-windows Release builds pass
  with Grasshopper installation disabled. This reduces the source-confirmed leak
  risk. In a copied build, an injected failure immediately after device creation
  and shader compilation, followed by a secondary cleanup exception, preserved the
  exact original `InvalidOperationException`; two solvers then reset and extracted
  correctly. This verifies the managed catch/rethrow and recovery path at one stage.
  It does not measure native release counts or inject a real COM `Dispose` failure.
  The final isolated injected build includes the `GetFields`/metadata-sort fallback
  hardening; final root net48/net7 builds and the normal Rhino graph also pass.
  An earlier isolated oversized-input attempt threw in `CreateVoxelFlagBuffer` after
  shader/density allocation and preserved the original `OverflowException`, but was
  removed after its stage assertion rejected the observed point; see handover/log.
  See constructor catch
  at lines 557–569 and cleanup at lines 6368–6511; the nested gradient wrapper
  independently attempts view and texture disposal at lines 4806–4841. A Rhino 9
  evaluation graph against this build successfully constructed/reset both solvers
  and retained R2 point/trail branches in both reset orders; this is successful-path
  evidence only and does not exercise failed construction.

### R2 · P1 · Particle extraction used another solver's global group registry — fixed and reproduced

- Sources: [registry replacement](Nuclei4/Solver_GPU.cs#L345),
  [point branching](Nuclei4/Particle_Extractor_Point.cs#L77),
  [trail branching](Nuclei4/Particle_Extractor_TrailPoints.cs#L87),
  [group assignment](Nuclei4/Gh1GpuSolverOutputSink.cs#L147).
- Evidence: each solver reset replaces `Globals.particleGroups`. Extractors find
  each particle's parent in that process-wide list and fall back to branch zero
  when absent. Reset solver B after solver A, then extract A's distinct groups:
  A's parents are absent from B's registry, so A's branches collapse to zero.
- Consequence: wrong Grasshopper tree grouping across independent simulations,
  potentially across open documents. Reproduced in an isolated two-solver Grasshopper graph; details below.
- Correction: carry/recover group order from the input particle output's owning
  session, preserving existing branch order and public identities. Add a two-solver
  reset-order regression with at least two groups and paused extraction.
